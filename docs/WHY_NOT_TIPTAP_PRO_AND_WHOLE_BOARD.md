# Почему не TipTap Pro / Cloud и не TipTap на всей доске

Кратко для команды и «О программе» — это **осознанные границы продукта**, а не недостаток TipTap.

## TipTap Pro / Cloud — не используем

| | MIT (то, что у нас) | Pro / Cloud |
|---|---------------------|-------------|
| **Лицензия** | Бесплатно, код в npm, без аккаунта | Платная подписка / облачный хостинг TipTap |
| **Редактор стикера** | `@tiptap/react`, StarterKit, table, link, color… — хватает | Pro-расширения (AI, advanced comments, export…) |
| **Совместное редактирование** | Можно на **Yjs** (open source) + свой Socket.IO | TipTap Cloud даёт готовый collab-backend — за деньги и с данными у вендора |
| **Зависимость** | Нет привязки к SaaS | Outage/тариф/политика TipTap влияют на прод |

**Вывод:** Pro/Cloud нужен, если хотите **готовый hosted collab + AI-фичи TipTap** без своего бэкенда. Retrogen — self-hosted ретро; collab делаем через **Yjs + существующий сервер**, редактор — только MIT-пакеты.

## TipTap на всей доске — не делаем

**Сейчас TipTap только внутри стикера** (`Card.text`). Остальное — другие подсистемы:

| Область | Сейчас | Почему не TipTap |
|---------|--------|------------------|
| Текст стикера | TipTap → HTML/JSON | Задача редактора |
| Блоки, колонки ретро | React + `planeState` | Не документ, а раскладка |
| Мемы, таймеры, фигуры | Canvas / gadgets | Не rich text |
| Связи стикеров | SVG + `connections` | Граф, не ProseMirror |
| Тема, лобби, отчёт | Отдельные страницы | Вне доски |

**Если «весь борд на TipTap»:**

- Один гигантский документ вместо сотен независимых стикеров — ломается модель «стикер = карточка в колонке».
- Конфликты, зум, перетаскивание, слои — смешиваются с редактированием текста.
- Бандл и память растут на всю доску; сейчас TipTap **lazy-load** только при edit стикера.

**Вывод:** TipTap — **движок поля стикера**. Доска остаётся React + plane state + socket (`planeLive`), как задумано в архитектуре Retrogen.
